Trayo GTM UI

The component library for go-to-market apps built on the Trayo API. Use it and your app looks like Trayo — the same colours, type, surfaces, buttons and tables, and the same treatment of the two things a GTM app renders constantly: people and companies, with real avatars and real logos.

Presentational React components only. No server-side logic, no data fetching, no auth.

Copy the files in — don't install from this URL

This URL is a delivery mechanism and will stop working. Copy the source into your application so the app stays self-contained. Do not npm install from this host: that records a disappearing URL in your package.json as a dependency spec, and every later install, CI run and fresh clone breaks the day it goes away.

From your project root:

mkdir -p src/trayo-ui
curl -L https://REPLACE_BASE/trayo-ui.tar.gz | tar xz -C src

You get src/trayo-ui/ with index.ts, components/, lib/ and styles/ (Polymath woff2 included), plus the README and AGENTS.md so the house rules live in your repo. No tar? Every file is readable on its own under ./src/, and files.txt lists every path.

Wire up the CSS

In your CSS entry, in this order:

@import "tailwindcss";
@import "./trayo-ui/styles/trayo-ui.css";

Tailwind must come first — the stylesheet extends its theme. No @source directive is needed: the components now sit in your own source tree, which Tailwind v4 already scans.

A whole app

import { AppShell, PageContainer, PageHeader, Person, CompanyCard, Button } from './trayo-ui'

export default function App() {
  return (
    <AppShell>
      <PageContainer>
        <PageHeader title="Target accounts" actions={<Button>Import</Button>} />
        <CompanyCard company={{ name: 'Ramp', domain: 'ramp.com', industry: 'Fintech' }} />
        <Person person={{ id: 'p-1', name: 'Dana Whitfield', title: 'VP RevOps',
                          company: 'Ramp', companyDomain: 'ramp.com' }} />
      </PageContainer>
    </AppShell>
  )
}

People and companies are the point

PersonLike and CompanyLike are loose supersets of GET /v1/people and GET /v1/accounts rows — pass an API object straight through and it renders whatever is there.

const { data } = await fetch('/v1/people?limit=25').then(r => r.json())
return data.map(p => <Person key={p.id} person={p} showContact />)

A person always gets a face: the real photo when it loads, otherwise one of 50 built-in illustrated fallbacks picked stably from the person id. Never initials. A company resolves its logo from its domain alone, through Trayo's public logo proxy.

House rules

  1. Rendering a person? <Person> or <PersonCard>. Never hand-assemble an avatar and a name.
  2. Rendering a company? <Company> or <CompanyCard>. Pass domain; never hand-write a logo <img>.
  3. Wrap the app in <AppShell> — it paints the branded canvas.
  4. Use the exported components before writing your own.
  5. No raw colours. Not #hex, not bg-slate-800. Use bg-surface-card, text-text-secondary, border-border-subtle, bg-accent-brand — they flip light/dark themselves.
  6. Content uses type roles (text-page-title, text-name, text-body, text-meta). Controls use text-sm font-medium. Never text-[15px].
  7. <Button loading> — don't swap in your own spinner.

What still touches the network

Two image paths resolve from Trayo production, not from this temporary host, so they keep working: company logos via api.trayo.ai/api/brand-image (public, no key) and the 50 fallback faces via app.trayo.ai/images/placeholder/. Prefer to self-host the faces? Grab placeholder-faces.tar.gz and set <TrayoUIProvider placeholderFaceBase="/images/placeholder">.
